Ты работаешь как ML/recommender engineering agent с доступом к репозиторию, терминалу и локальным файлам.

ЗАДАЧА

Сделай отдельный полностью рабочий Python-рекомендатель музыки:

python recommend.py tracks.txt

Вход:
до 2000 строк вида:

Nirvana - Lithium
Nirvana - Heart-Shaped Box
Metallica - One

Выход:
50 лучших новых треков:

rank | artist | title | neural_score | taste_head | graph_support

МИНИМАЛЬНЫЙ означает только отсутствие UI, сайта, TypeScript, Vercel, браузерной оптимизации и playback.

НЕ УПРОЩАЙ САМУ РЕКОМЕНДАТЕЛЬНУЮ СИСТЕМУ.

==================================================
ГЛАВНОЕ ОПРЕДЕЛЕНИЕ
==================================================

ЭТО ДОЛЖНА БЫТЬ МОЯ СОБСТВЕННАЯ ИИ.

Обязательные признаки:

- neural network;
- random initialization;
- trainable weights;
- loss;
- backpropagation;
- optimizer updates;
- checkpoints;
- inference на обученных весах.

Human graph, ANN/HNSW, PPR, affinity formulas и filters НЕ являются моей ИИ.
Это инфраструктура и данные вокруг моей ИИ.

Запрещено выдавать их за AI.

Запрещено использовать:

- OpenAI/LLM внутри recommender;
- Spotify recommendations;
- Last.fm recommendations;
- pretrained recommender;
- pretrained embeddings;
- pretrained graph model;
- genre rules;
- artist whitelist;
- artist blacklist;
- ручное правило "Nirvana = grunge";
- handcrafted bonuses после neural score.

==================================================
КОНЕЧНАЯ АРХИТЕКТУРА
==================================================

Система должна работать так:

REAL HUMAN LISTENING DATA
        ↓
clean track identities
        ↓
TWO HUMAN SIGNALS

1. TRACK ↔ USER
   долгосрочный вкус

2. TRACK ↔ SESSION
   локальный музыкальный контекст

        ↓
clean human graph
        ↓
МОЙ GraphEncoder
random init + backprop
        ↓
learned music embeddings
        ↓
tracks.txt пользователя
        ↓
МОЯ Multi-Interest neural network
        ↓
несколько независимых taste vectors
        ↓
graph-gated candidate RANGE
для каждого taste отдельно
        ↓
МОЙ neural ranker
        ↓
TOP 50

Не заменяй эту архитектуру одним average embedding.

==================================================
ВАЖНО: РЕАЛЬНАЯ ЗАДАЧА
==================================================

Это НЕ next-song predictor.

Пользователь даёт набор от нескольких до 2000 любимых треков без значимого порядка.

Модель должна понять долгосрочные музыкальные вкусы пользователя.

Training examples должны соответствовать production:

реальная библиотека пользователя
→ часть его треков hidden
→ оставшиеся tracks являются seeds
→ модель должна найти hidden tracks среди большого каталога.

Sessions нужны как дополнительный human signal для построения пространства, но основная objective должна соответствовать задаче:

SET OF LIKED TRACKS → MORE LIKED TRACKS.

==================================================
MILESTONE 3 — ДВА HUMAN GRAPH SIGNALS
==================================================

Не делай только:

TRACK ↔ SESSION.

Нужны отдельно:

A. LONG TERM GRAPH

TRACK ↔ USER

Он показывает:
какие треки устойчиво присутствуют у одних и тех же людей во времени.

B. LOCAL CONTEXT GRAPH

TRACK ↔ SESSION

Он показывает:
какие треки встречаются рядом внутри реальных listening contexts.

Не схлопывай эти два смысла в один raw count.

Для отношений track-track храни отдельно:

global_user_affinity
local_session_affinity
support_users
support_sessions
confidence

==================================================
ОЧИСТКА GRAPH
==================================================

Не считать каждый listen одинаковым доказательством.

Уменьшать влияние:

- одного сверхактивного user;
- repeated loops;
- A A A A;
- огромных sessions;
- одного полного album run;
- bot-like activity;
- сверхпопулярных tracks;
- одного-единственного co-occurrence;
- огромных библиотек пользователя.

Повторные подтверждения от одного человека должны saturate.

Сильное relation требует НЕЗАВИСИМЫХ users.

Popularity correction обязательна.

Нельзя:

popular A + popular B
→ автоматически strong relationship.

Используй статистически нормализованную association,
но НЕ доверяй raw PMI для редких пар.

Rare pair с большим PMI и двумя users должна иметь низкую confidence.

Сохрани raw graph statistics.

==================================================
MILESTONE 7 — МОЯ ИИ: GRAPH ENCODER
==================================================

Реализуй небольшой собственный trainable GraphEncoder на PyTorch.

Ориентир:
LightGCN-like propagation.

Но НЕ импортируй pretrained implementation/weights.

Обязательное:

random TrackEmbedding
random UserEmbedding
graph propagation
96D output
loss
optimizer
loss.backward()
optimizer.step()
checkpoint

2 propagation layers — разумный старт.

Не делай огромную архитектуру без доказанной необходимости.

==================================================
GRAPH TRAINING OBJECTIVE
==================================================

Основная задача:

реальные human relationships
должны получать большую similarity,
чем неправдоподобные candidates.

Negative pool должен содержать смесь:

- random;
- popularity-matched;
- medium negatives;
- hard negatives.

НЕ повторять старый проёб:

1 positive + 1 random negative.

Но также НЕ считать:

"нет прямого edge"
=
"точно negative".

Hard candidate нельзя считать negative,
если есть:

- strong 2-hop graph evidence;
- strong user overlap;
- strong session evidence;
- другая существенная human support.

Не обучай модель отталкивать потенциально хорошие discoveries.

Используй multi-negative contrastive/listwise objective.

==================================================
MILESTONE 8 — GRAPH ENCODER EVALUATION
==================================================

После каждой epoch считать DEV metrics.

Не считать train loss доказательством качества.

Особенно помни прошлый проёб:
train loss сильно падал,
а validation почти не улучшалась.

Обязательно:

Recall@10
Recall@50
Recall@100
NDCG@10
NDCG@50
MRR

Сравнить:

trained
random
popularity
graph baseline
degree-preserving shuffled graph

SHUFFLED CONTROL:

shuffle должен сохранять user degree и track degree настолько возможно,
разрушая реальные пары USER↔TRACK.

Простой random shuffle, меняющий popularity distribution, запрещён.

Если trained практически равен shuffled:
GRAPH_ENCODER_FAIL.

Если trained проигрывает strong graph baseline:
не объявлять победу.

==================================================
MILESTONE 9 — FULL CATALOG EVALUATION
==================================================

Не повторять прошлую лазейку:

1 positive + 99 random candidates.

Основные ranking metrics считать по полному допустимому seen catalog
либо exact/full-ranking способом.

Небольшой sampled evaluation допускается только как быстрый debug metric,
но НЕ release evidence.

==================================================
MILESTONE 10 — МОЯ ИИ ДЛЯ НЕСКОЛЬКИХ ВКУСОВ
==================================================

В production пользователь даёт SET из треков.

Порядок строк не имеет смысла.

Поэтому taste model должна быть permutation-invariant.

Никакого RNN по порядку строк.

Не делать:

mean(all 2000 embeddings).

Сделать trainable multi-interest/set network.

Например:

track embeddings
→ learned projections/attention
→ soft assignment
→ максимум K taste heads
→ normalized taste vectors

Kmax = 16 для начала.

Количество реально активных heads должно быть динамическим.

Пустые heads отключать.

Добавить защиту от head collapse.

==================================================
TASTE TESTS
==================================================

Обязательно:

1. permutation test:
перемешивание tracks.txt практически не меняет рекомендации.

2. duplicate test:
10 повторов одного seed не должны захватывать taste.

3. mixed taste:
смешанные реальные профили должны получать несколько distinct heads.

4. stability:
удаление случайных 10–20% большой библиотеки не должно полностью ломать основные heads.

Если heads схлопнулись:
TASTE_FAIL.

==================================================
MILESTONE 11 — RANGE GENERATOR
==================================================

Это КРИТИЧЕСКАЯ часть.

Neural ranker НЕ должен видеть весь каталог.

Для КАЖДОГО taste head отдельно:

seeds / taste vector
↓
clean graph diffusion
+
GraphEncoder neighbourhood
↓
human confidence gate
↓
candidate range

Не брать "Top 2000 любой ценой".

Использовать calibrated radius / confidence threshold.

Когда заканчивается human-supported neighbourhood:
range заканчивается.

Разрешено получить:

700 кандидатов

вместо заполнения до 2000 мусором.

==================================================
ГЛАВНАЯ ЗАЩИТА ОТ ARIANA BUG
==================================================

Кандидат без достаточного human graph evidence для данного taste range
НЕ передаётся neural ranker.

Следовательно случайный далёкий popular track не должен иметь возможность попасть в TOP50 только потому, что neural score ошибся.

Но НЕ писать:

Ariana blacklist
Nirvana whitelist
genre filter.

Защита должна быть общей для любых tracks.

MILESTONE 12 — RANGE EVALUATION

@2000

==================================================
RANKER TRAINING
==================================================

Training distribution должна совпадать с production.

Создай profile examples из реальных пользователей:

user library
↓
hide часть tracks
↓
остальные = seeds
↓
построить taste heads
↓
запустить ТОТ ЖЕ production range
↓
hidden real tracks = positives
↓
остальные реальные range candidates = negative/unknown candidates
↓
train ranker

Не обучать ranker преимущественно на random catalog negatives.

==================================================
FINAL SCORE
==================================================

final_score = neural ranker output.

НЕ:

neural
+ popularity bonus
+ rarity bonus
+ genre bonus
+ graph bonus.

Graph evidence входит как feature в neural network и как candidate gate,
но после neural output ручных музыкальных score additions нет.

После scoring разрешены только технические ограничения:

- remove input tracks;
- remove exact duplicates;
- remove explicit dislikes;
- artist cap для presentation.

Evaluation проводить ДО artist cap тоже,
чтобы cap не скрывал плохую модель.

==================================================
RELEASE EVIDENCE
==================================================

Нельзя писать DONE только потому, что:

- код запускается;
- loss падает;
- weights изменились;
- одна красивая recommendation выглядит нормально.

Нужны реальные доказательства.

Минимум сравнить:

POPULARITY
GRAPH BASELINE
RANDOM NETWORK
DEGREE-PRESERVING SHUFFLED GRAPH
TRAINED GRAPH ENCODER
FINAL NEURAL SYSTEM

Используй несколько random seeds обучения.

Если результат существует только на одном seed:
считать нестабильным.

Для сравнений на user queries считать paired uncertainty,
например bootstrap confidence intervals.
