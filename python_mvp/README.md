# Удобный CLI: пробовать разные музыкальные профили

Из корня проекта:

```bash
python -m python_mvp.cli
```

CLI использует готовые веса `data/discovery-v3`, загружает модель один раз и
**никогда не запускает обучение, оценку датасета или скачивания**.

- `1` — загрузить JSON, CSV или TXT (можно перетащить файл в терминал).
- `2` — вставить строки `Artist - Title`; пустая строка завершает ввод.
- `3` — получить плейлист.
- `4` — выбрать смешанную выдачу, открытия или чистый порядок нейросети.
- `5` — загрузить полную библиотеку уже знакомого для исключения из выдачи.
- `6` — отметить номера знакомых песен; они исключатся при следующей выдаче.
- `7` — посмотреть нераспознанные названия; `0` — выйти.

Смешанный режим: максимум два трека исполнителя, без обязательной квоты новых.
Открытия: максимум два трека исполнителя и не более 30% треков знакомых исполнителей.
Чистый порядок сети: без ограничений по исполнителям. Во всех режимах введённые
песни и распознанные варианты исключаются. «Новый исполнитель» означает только
отсутствие в загруженных списках, не гарантирует, что ты его не слышал.

Можно сразу открыть свой список:

```bash
python -m python_mvp.cli ~/Downloads/liked.json
```

Или один раз получить выдачу по небольшому профилю, исключив всю библиотеку:

```bash
python -m python_mvp.cli tracks.txt --known ~/Downloads/liked.json --once
```

Каждая выдача сохраняется отдельно в `python_mvp/data/cli-playlists/`: `playlist.txt`,
`unresolved.txt` и `result.json` с входом, исключениями, режимом и баллами.
Отметки из меню живут в текущей сессии и попадают в JSON следующей выдачи.
Все эти личные файлы игнорируются Git. Другую папку весов можно указать через `--run`.
Отсутствующие или несовместимые веса дают понятную ошибку, без автоматического обучения.

CLI теперь допускает явно отмеченные совпадения по названию: если рядом с MBID
есть единственная metadata-запись с точным артистом и названием, для профиля
используется эта запись без MBID. Разные записи не склеиваются, MBID не угадывается.
Также допускается однозначное совпадение после удаления только метки ремастера;
live/remix/acoustic не удаляются. Такие совпадения показаны отдельно и записаны
в `result.json → matching`. Прежний строгий режим: `--strict-matching`.
Это расширяет профиль, но само по себе не доказывает улучшения рекомендаций.

Честное сравнение текущих весов с простыми методами на одинаковых кандидатах и
одинаковых ограничениях готового плейлиста (без обучения и frozen final):

```bash
python -m python_mvp.audit_discovery
```

Результат — `data/discovery-v3/fair_audit_mode2.json`. Для смешанного режима:
`--mode 1`. Это диагностическая оценка на DEV, включающем пользователей выбора
модели, а не независимое подтверждение качества. Старые отчёты сохраняются.

Модель экспериментальная. Не все входные треки есть в каталоге; счётчик распознавания
показывается для каждого профиля. Качество сети пока уступает сильнейшему измеренному
методу по похожим слушателям. CLI предназначен для проверки реальных рекомендаций,
а не обозначает прохождение release-проверок.

# Свой нейронный рекомендатель: запуск из терминала

Это отдельный Python-проект. Production-сайт не меняется.
GraphEncoder, multi-interest routing и neural ranker обучаются с нуля.
Нет pretrained embeddings, LLM, жанровых правил, Spotify recommendations или аудио.
**Качество TOP50 пока не доказано. Команда обучения может честно закончиться FAIL.**

## Обновление на уже скачанных данных (без сети)

Из корня репозитория одна команда:

```bash
python -m python_mvp.refresh
```

Она создаёт `python_mvp/data/discovery-v1`, явно импортирует неизменённые
графовые векторы из `data/main` с проверкой данных и словаря и сохранением
исходного контракта. Граф и аудио не обучаются. Обучаются Taste и новый
NeuralRanker (seed 42), затем вычисляются DEV-метрики. При ошибке качества
команда останавливается, не объявляя успех. Исходный эксперимент не меняется.
Для трёх seeds: `python -m python_mvp.refresh --seeds 42 43 44 --run python_mvp/data/discovery-three`.

После успешного DEV:

```bash
MUSICMVP_RUN="$PWD/python_mvp/data/discovery-v1" python -m python_mvp.recommend tracks.txt --experimental
```

`tracks.txt`: до 2000 строк `Artist - Title` (также `Artist — Title`) или Recording MBID.
Выдача содержит до 50 треков за пределами введённой библиотеки; знакомые исполнители
могут остаться. Что ты слышал вне переданного списка, система знать не может.
Неоднозначные совпадения исключаются из выдачи, но не используются как векторы вкуса.

**В `data/main` финальный тест уже использован.** Его блокировка переносится в новый
эксперимент: переобучение не создаёт новый независимый тест. Результат остаётся
экспериментальным. Для нового доказательства качества потребуются новые нетронутые
пользователи; повторный FAIL нельзя превращать в PASS подбором по тем же final users.

### Что изменилось в discovery-v1

- Половина тренировочных эпизодов скрывает исполнителя целиком (только TRAIN users).
- Граф извлекает до 2000 кандидатов, учитывая калиброванный на DEV радиус.
- Кандидат оценивается относительно всех активных вкусов, итог — максимальный neural score.
- Одна обучаемая fusion-сеть получает векторы, взаимодействия и evidence, без фиксированной смеси баллов.
- Контракты проверяют код; ошибки стабильности приводят к FAIL; проверяется точный порядок и scores.
- Отдельные старые audio-эксперименты сохранены, но основной pipeline от них не зависит.
  Графовая близость **не является анализом звучания**.

Сбор нового датасета, только если он действительно нужен:

```bash
python python_mvp/run_pipeline.py all --run python_mvp/data/new-run --days 14 --user-fraction 0.25
```

Эта отдельная команда скачивает данные и обучает всё. `refresh` этого не делает.
Все данные, веса и новые отчёты внутри `data/` игнорируются Git.

Для нового компьютера:

```bash
python -m venv --system-site-packages .venv
.venv/bin/python -m pip install -r requirements.txt
# zstd устанавливается системным пакетным менеджером
.venv/bin/python run_pipeline.py all --days 14 --user-fraction 0.25
```

Подробное состояние и точные команды диагностики: [HANDOFF.md](HANDOFF.md).

## Что защищено кодом

- User splits до graph fit; разные user/session сигналы; отдельные support/confidence.
- MBID не подменяется MSID. Разные recordings сохраняются; ambiguous input unresolved.
- Нет random/cold embeddings в recommendable catalog и heuristic fallback.
- Checkpoints привязаны к dataset, split, graph, ordered vocabulary, model config,
  implementation hashes, seed, epoch и DEV metrics. Несовместимость — ошибка.
- Negatives исключают все известные positives и сильную человеческую поддержку.
- Перестановки/дубли seeds не меняют taste inference. Несколько routing heads,
  проверка collapse, устойчивости и смешанных реальных профилей.
- Радиус и confidence калибруются только по DEV. Ranker обучается на том же range,
  что использует выдача. Итоговый score исключительно neural output.
- Full-catalog metrics, graph/popularity/PPR/random/trained-shuffled controls,
  candidate recall, разные размеры профилей, cross-artist test, paired uncertainty.

## Практические ограничения

Выборка из incremental dumps — **не весь ListenBrainz и не полная история каждого**.
14 дней обозначают окно поступления данных, не обязательно время прослушивания.
Это implicit listening positives, а не явные лайки. Данных может не хватить для
устойчивого качества; downloader не гарантирует прохождения ML quality gates.
Большие библиотеки >2000 уникальных треков пока исключены из graph fitting,
но остаются в датасете; это ограничение покрытия, а не музыкальное правило.
Graph co-occurrences считаются блоками, однако итоговые sparse matrices и
preprocessed dataset всё ещё должны помещаться в RAM. Начните с указанной выборки.

Официальный формат и происхождение:
https://listenbrainz.readthedocs.io/en/latest/users/listenbrainz-dumps.html
https://data.metabrainz.org/pub/musicbrainz/listenbrainz/incremental/

Исходное задание — REQUIREMENTS.txt. Более позднее указание пользователя имеет
приоритет: сначала сложный код, сбор/обучение автоматизировать, PLAN.md не создавать.
