# Удобный CLI: пробовать разные музыкальные профили

Из корня проекта:

```bash
python -m python_mvp.cli
```

CLI использует готовые веса `data/discovery-v3`, загружает модель один раз и
**никогда не запускает обучение, оценку датасета или скачивания**.

- `1` — загрузить JSON, CSV или TXT (можно перетащить файл в терминал).
- `2` — вставить строки `Artist - Title`; пустая строка завершает ввод.
- `3` — получить плейлист.
- `4` — выбрать смешанную выдачу, открытия или чистый порядок нейросети.
- `5` — загрузить полную библиотеку уже знакомого для исключения из выдачи.
- `6` — отметить номера знакомых песен; они исключатся при следующей выдаче.
- `7` — посмотреть нераспознанные названия; `0` — выйти.
- `ещё как 3 7 12` — сразу получить плейлист в направлении выбранных песен из
  последней выдачи (также работает `еще как`, диапазоны вроде `1-3`). Граф ищет
  кандидатов по этим записям, затем готовая нейросеть ранжирует их заново.
  Исходная библиотека, загруженное знакомое и выбранные в этой сессии песни
  исключаются. Команда не ставит лайки и не запускает обучение.
- `весь профиль` — сразу вернуться к поиску по исходной библиотеке.
  До сброса пункт `3` использует выбранное направление; загрузка нового профиля
  через `1` или `2` также сбрасывает направление. Направление сохраняется в
  `result.json → focus`, исходный список — в `library_input`.

Смешанный режим: максимум два трека исполнителя, без обязательной квоты новых.
Открытия: максимум два трека исполнителя и не более 30% треков знакомых исполнителей.
Чистый порядок сети: без ограничений по исполнителям. Во всех режимах введённые
песни и распознанные варианты исключаются. «Новый исполнитель» означает только
отсутствие в загруженных списках, не гарантирует, что ты его не слышал.

Можно сразу открыть свой список:

```bash
python -m python_mvp.cli ~/Downloads/liked.json
```

Или один раз получить выдачу по небольшому профилю, исключив всю библиотеку:

```bash
python -m python_mvp.cli tracks.txt --known ~/Downloads/liked.json --once
```

Каждая выдача сохраняется отдельно в `python_mvp/data/cli-playlists/`: `playlist.txt`,
`unresolved.txt` и `result.json` с входом, исключениями, режимом и баллами.
Отметки из меню живут в текущей сессии и попадают в JSON следующей выдачи.
Все эти личные файлы игнорируются Git. Другую папку весов можно указать через `--run`.
Отсутствующие или несовместимые веса дают понятную ошибку, без автоматического обучения.

CLI теперь допускает явно отмеченные совпадения по названию: если рядом с MBID
есть единственная metadata-запись с точным артистом и названием, для профиля
используется эта запись без MBID. Разные записи не склеиваются, MBID не угадывается.
Также допускается однозначное совпадение после удаления только метки ремастера;
live/remix/acoustic не удаляются. Такие совпадения показаны отдельно и записаны
в `result.json → matching`. Прежний строгий режим: `--strict-matching`.
Это расширяет профиль, но само по себе не доказывает улучшения рекомендаций.

Честное сравнение текущих весов с простыми методами на одинаковых кандидатах и
одинаковых ограничениях готового плейлиста (без обучения и frozen final):

```bash
python -m python_mvp.audit_discovery
```

Результат — `data/discovery-v3/fair_audit_mode2.json`. Для смешанного режима:
`--mode 1`. Это диагностическая оценка на DEV, включающем пользователей выбора
модели, а не независимое подтверждение качества. Старые отчёты сохраняются.

Модель экспериментальная. Не все входные треки есть в каталоге; счётчик распознавания
показывается для каждого профиля. Качество сети пока уступает сильнейшему измеренному
методу по похожим слушателям. CLI предназначен для проверки реальных рекомендаций,
а не обозначает прохождение release-проверок.

# Свой нейронный рекомендатель: запуск из терминала

Это отдельный Python-проект. Production-сайт не меняется.
GraphEncoder, multi-interest routing и neural ranker обучаются с нуля.
Нет pretrained embeddings, LLM, жанровых правил, Spotify recommendations или аудио.
**Качество TOP50 пока не доказано. Команда обучения может честно закончиться FAIL.**

## Обновление на уже скачанных данных (без сети)

Из корня репозитория одна команда:

```bash
python -m python_mvp.refresh
```

Она создаёт `python_mvp/data/discovery-v1`, явно импортирует неизменённые
графовые векторы из `data/main` с проверкой данных и словаря и сохранением
исходного контракта. Граф и аудио не обучаются. Обучаются Taste и новый
NeuralRanker (seed 42), затем вычисляются DEV-метрики. При ошибке качества
команда останавливается, не объявляя успех. Исходный эксперимент не меняется.
Для трёх seeds: `python -m python_mvp.refresh --seeds 42 43 44 --run python_mvp/data/discovery-three`.

После успешного DEV:

```bash
MUSICMVP_RUN="$PWD/python_mvp/data/discovery-v1" python -m python_mvp.recommend tracks.txt --experimental
```

`tracks.txt`: до 2000 строк `Artist - Title` (также `Artist — Title`) или Recording MBID.
Выдача содержит до 50 треков за пределами введённой библиотеки; знакомые исполнители
могут остаться. Что ты слышал вне переданного списка, система знать не может.
Неоднозначные совпадения исключаются из выдачи, но не используются как векторы вкуса.

**В `data/main` финальный тест уже использован.** Его блокировка переносится в новый
эксперимент: переобучение не создаёт новый независимый тест. Результат остаётся
экспериментальным. Для нового доказательства качества потребуются новые нетронутые
пользователи; повторный FAIL нельзя превращать в PASS подбором по тем же final users.

### Что изменилось в discovery-v1

- Половина тренировочных эпизодов скрывает исполнителя целиком (только TRAIN users).
- Граф извлекает до 2000 кандидатов, учитывая калиброванный на DEV радиус.
- Кандидат оценивается относительно всех активных вкусов, итог — максимальный neural score.
- Одна обучаемая fusion-сеть получает векторы, взаимодействия и evidence, без фиксированной смеси баллов.
- Контракты проверяют код; ошибки стабильности приводят к FAIL; проверяется точный порядок и scores.
- Отдельные старые audio-эксперименты сохранены, но основной pipeline от них не зависит.
  Графовая близость **не является анализом звучания**.

Сбор нового датасета, только если он действительно нужен:

```bash
python python_mvp/run_pipeline.py all --run python_mvp/data/new-run --days 14 --user-fraction 0.25
```

Эта отдельная команда скачивает данные и обучает всё. `refresh` этого не делает.
Все данные, веса и новые отчёты внутри `data/` игнорируются Git.

Для нового компьютера:

```bash
python -m venv --system-site-packages .venv
.venv/bin/python -m pip install -r requirements.txt
# zstd устанавливается системным пакетным менеджером
.venv/bin/python run_pipeline.py all --days 14 --user-fraction 0.25
```

Подробное состояние и точные команды диагностики: [HANDOFF.md](HANDOFF.md).

## Что защищено кодом

- User splits до graph fit; разные user/session сигналы; отдельные support/confidence.
- MBID не подменяется MSID. Разные recordings сохраняются; ambiguous input unresolved.
- Нет random/cold embeddings в recommendable catalog и heuristic fallback.
- Checkpoints привязаны к dataset, split, graph, ordered vocabulary, model config,
  implementation hashes, seed, epoch и DEV metrics. Несовместимость — ошибка.
- Negatives исключают все известные positives и сильную человеческую поддержку.
- Перестановки/дубли seeds не меняют taste inference. Несколько routing heads,
  проверка collapse, устойчивости и смешанных реальных профилей.
- Радиус и confidence калибруются только по DEV. Ranker обучается на том же range,
  что использует выдача. Итоговый score исключительно neural output.
- Full-catalog metrics, graph/popularity/PPR/random/trained-shuffled controls,
  candidate recall, разные размеры профилей, cross-artist test, paired uncertainty.

## Практические ограничения

Выборка из incremental dumps — **не весь ListenBrainz и не полная история каждого**.
14 дней обозначают окно поступления данных, не обязательно время прослушивания.
Это implicit listening positives, а не явные лайки. Данных может не хватить для
устойчивого качества; downloader не гарантирует прохождения ML quality gates.
Большие библиотеки >2000 уникальных треков пока исключены из graph fitting,
но остаются в датасете; это ограничение покрытия, а не музыкальное правило.
Graph co-occurrences считаются блоками, однако итоговые sparse matrices и
preprocessed dataset всё ещё должны помещаться в RAM. Начните с указанной выборки.

Официальный формат и происхождение:
https://listenbrainz.readthedocs.io/en/latest/users/listenbrainz-dumps.html
https://data.metabrainz.org/pub/musicbrainz/listenbrainz/incremental/

Исходное задание — REQUIREMENTS.txt. Более позднее указание пользователя имеет
приоритет: сначала сложный код, сбор/обучение автоматизировать, PLAN.md не создавать.

### Исправленное обучение без пересечения пользователей

Из корня репозитория, без скачиваний и без открытия FINAL:

```bash
python -m python_mvp.honest_training
```

Команда читает существующий `python_mvp/data/main/data/dataset.json` и создаёт
**новый** `python_mvp/data/honest-v1`. Заново обучает графовые векторы, модель
интересов и финальный нейронный ранжировщик. Старые веса не импортируются и не
перезаписываются. `--check-only` выполняет только предварительную проверку без
построения графа и обучения. Повторный эксперимент требует нового `--run`.

После обучения открыть прежний удобный CLI с новыми весами:

```bash
python -m python_mvp.cli --run python_mvp/data/honest-v1 --mode 2
```

Что исправлено в этой ветке эксперимента:

- Исходные TRAIN-пользователи детерминированно разделены 70/30: граф/векторы/
  интересы обучаются на первой группе, финальный ранжировщик — на второй.
  Все его признаки считаются без истории самого обучаемого пользователя в графе.
- Поддержка трека считается по реальным оставшимся строкам графа. Пользователи
  с проекцией меньше двух треков и треки с поддержкой меньше трёх пользователей
  удаляются до стабилизации.
- Положительные и неизвестные учебные сравнения находятся в том же наборе
  кандидатов, что и на выдаче. Известные позитивы и возможные варианты по
  названиям/алиасам защищены от негативного семплирования, включая известные
  записи, чей исходный ID не вошёл в каталог. Неизвестное не означает дизлайк.
- Варианты одной песни не разделяются между seed/target. Это осторожная
  группировка для исключения, а не подтверждение одинаковой аудиозаписи.
- DEV сравнивает нейросеть, слушателей, PPR и граф на **одних кандидатах** и
  **одинаковом плейлисте**: до 50, максимум 2 трека исполнителя, максимум 30%
  знакомых исполнителей. Выбор эпохи учитывает именно такую выдачу и открытия.
- `sampling.json` показывает пропущенные эпизоды/доступность целей;
  `evaluation.json` содержит метрики и парные интервалы. Если преимущество
  над базовыми методами не подтверждается на DEV, статус `NO_PROVEN_DEV_GAIN`.
  CLI позволяет прослушать эксперимент и с этим статусом; автоматической
  подмены нейросети базовым методом нет.

Ограничения: DEV уже использовался для прежних экспериментов и используется
для выбора эпохи; эти интервалы не являются независимым тестом качества.
Исходный FINAL остаётся закрытым, его отметка использования сохраняется.
Реестр названий/алиасов исходного датасета уже общий для всех сплитов: строгая
изоляция касается взаимодействий и пользователей, а не происхождения метаданных.
Переучивание уменьшает каталог; пропавшие из кандидатов песни ранжировщик не
может вернуть. Улучшение вкусового качества заранее не гарантируется.
Новый Python-путь экспериментальный и не меняет TypeScript-приложение.

### Дообучение финального ранжировщика на готовом honest-v1

Если `honest-v1` уже обучен, **не запускайте заново обучение графа**:

```bash
python -m python_mvp.refine_ranker
```

Команда проверяет существующие граф, векторы, разделение пользователей и веса;
учит только небольшую нейронную поправку к порядку по похожим слушателям.
Она не скачивает данные, не расширяет каталог и не переобучает граф/интересы.
`--check-only` проверяет совместимость без обучения. Результат — `data/refined-v1`.

Отличия от предыдущего ранжировщика:

- Начальный порядок **точно совпадает** с методом похожих слушателей.
  Нейросеть учит ограниченную поправку; она не тратит первые эпохи на восстановление
  базового порядка из случайной инициализации.
- Положительный трек сравнивается с неизвестными треками той же категории
  «знакомый/незнакомый исполнитель». Простого предпочтения знакомым исполнителям
  недостаточно для уменьшения этой функции потерь.
- Пользователи имеют одинаковый суммарный вес независимо от размера библиотеки;
  на пользователя создаются несколько воспроизводимых эпизодов.
- Подготовленные примеры, оптимизатор и генератор случайных чисел сохраняются.
  Та же команда продолжает прерванный запуск. Если запуск завершён, она проверяет
  готовую модель и печатает команду CLI без повторного обучения.
- Изменение кода, исходного эксперимента или параметров требует другого `--run`.
  Существующие модели никогда не перезаписываются другим экспериментом.
- Для отбора сохраняется не более 120 DEV-профилей в памяти; полный отчёт
  считается последовательно. Результаты неизменных базовых методов кешируются.

Отбор эпох требует не ухудшить одновременно общую NDCG и NDCG новых исполнителей
относительно базового метода на выборке DEV и повысить сумму этих метрик.
Это **не гарантия качества** на других пользователях: DEV уже использовался.
Полные парные сравнения доступны в `data/refined-v1/evaluation.json`.
Если ни одна эпоха не проходит отбор, статус будет
`LISTENER_BASELINE_NO_ACCEPTED_NEURAL_GAIN`: CLI явно сообщает, что используется
базовый метод. Обученный, но не принятый кандидат отдельно сохранён в `candidate.pt`.
Его нельзя выдавать за доказанное улучшение.

После обучения:

```bash
python -m python_mvp.cli ~/Downloads/liked.json --run python_mvp/data/refined-v1 --mode 2
```

Без `--run` CLI выбирает готовый `refined-v1`, затем `honest-v1`, затем
`discovery-v3`; неполные эксперименты пропускаются. Путь выбранной модели выводится.

### Расширить данные из уже скачанных архивов

Если нейронная поправка отклонена и большинство личных треков отсутствует в
каталоге, повторное обучение тех же примеров не добавит недостающую музыку.
В текущем `main` использовались 25% пользователей трёх исходных архивов;
полные архивы сохранены локально. Использовать все их данные можно без сети:

```bash
python -m python_mvp.expand_data
```

Создаётся отдельный `python_mvp/data/expanded-v1`. Команда:

- проверяет SHA-256 оригинальных архивов по сохранённому отчёту коллектора;
- извлекает 100% пользователей, сохраняя готовые этапы для повторного запуска;
- сохраняет исходное назначение TRAIN/DEV/SHADOW/FINAL для каждого старого
  пользователя; новые пользователи получают сплит по тому же правилу;
- переносит отметку ранее использованного FINAL и не оценивает его;
- распределяет события по временным файлам пользователей и пишет итоговый JSON
  потоком. Метаданные каталога/индекс всё ещё хранятся в памяти, поэтому расход
  RAM не константный. На диске нужны место для распакованных JSONL и временных
  событий; архивы повторно не копируются;
- не скачивает данные, не обучает сети и не меняет старые эксперименты.

`--check-only` проверяет архивы и конфигурацию без распаковки. После завершения
команда печатает точный запуск обучения на новом датасете:

```bash
python -m python_mvp.honest_training --source python_mvp/data/expanded-v1 --run python_mvp/data/expanded-v1/model
```

Это расширение выборки **из тех же трёх публикаций**, а не полный архив истории
ListenBrainz. Фактический размер и качество новой выборки будут известны после
подготовки и обучения. Никакого обещания роста метрик здесь нет; старые модели
остаются доступными для сравнения. Если подготовка уже завершена, повторная
команда проверяет файлы и ничего заново не обрабатывает.

### Личные оценки и обучение на своём вкусе

Перезапустите CLI, чтобы загрузить новый интерфейс. По умолчанию он теперь
выбирает готовую модель `expanded-v1/model` перед старыми экспериментами:

```bash
python -m python_mvp.cli ~/Downloads/liked.json --mode 2
```

После выдачи вводите команды прямо вместо номера меню:

```text
лайк 8 19 29
дизлайк 14 21
знаю 1-7
новое 8 19
сброс 14
отмена
```

- `лайк`/`дизлайк` — предпочтение, `знаю`/`новое` — знакомство с песней.
  Они независимы. Пропуски не становятся дизлайками.
- Номера относятся к последней показанной выдаче. Можно менять оценку;
  `сброс` снимает предпочтение, `отмена` отменяет последнюю группу действий.
- Журнал сохраняется атомарно в игнорируемой `python_mvp/data/personal/feedback.json`.
  Сохраняются версия общей модели, профиль, позиция трека, признаки и идентификатор
  выдачи. Для разных людей используйте разные папки `--feedback`.
- Дизлайки исключаются; в режиме открытий дополнительно исключаются знакомые
  и уже оценённые песни. Лайк не объявляет весь каталог исполнителя любимым.
- Пункт **5** сохраняет полную знакомую библиотеку между запусками. Для неё нет
  лимита 2000 треков профиля. Импорт можно отменить командой `отмена`.
- Пункт **9** показывает счётчики и команды обновления/отката личной модели.

Обновление — отдельная короткая команда; CLI никогда сам не обучается:

```bash
python -m python_mvp.personal train --run python_mvp/data/expanded-v1/model
```

Нужно минимум 20 разных оценённых треков, минимум 5 лайков и 5 дизлайков,
из минимум 3 выдач. Это минимальная техническая проверка, не обещание качества.
Может потребоваться больше данных, если поздние оценки не позволяют проверить
ранжирование или ранние не содержат оба класса.

Личный слой — регуляризованная логистическая модель над графовым вектором
трека и признаками контекста рекомендации. Она обучает ограниченную поправку
к общей модели; граф не переобучается. Доля поправки растёт постепенно.

Последние оценки отложены для временной валидации. Одна выдача не пересекает
обучение и проверку: более ранние строки пересекающихся выдач исключаются.
Поздняя правка старого лайка не переносит будущую оценку в обучение.
Активация требует меньшей ошибки предпочтений, чем у константной частоты лайков,
и отсутствия ухудшения порядка лайк/дизлайк относительно общей модели внутри
отложенных выдач. Валидация используется для активации, поэтому это не независимый
финальный тест и не гарантия улучшения всех будущих рекомендаций.

Отклонённый кандидат сохраняется, но предыдущая модель остаётся активной.
Отмена/изменение использованной обучающей или проверочной оценки отключает
несовместимый слой. Новая общая модель требует нового личного обучения;
старые векторы с новыми весами не смешиваются.

```bash
python -m python_mvp.personal status
python -m python_mvp.personal rollback
python -m python_mvp.cli ~/Downloads/liked.json --mode 2 --no-personal
```

Откат не удаляет оценки. `--no-personal` отключает поправку для сравнения,
но сохраняет исключение дизлайков и знакомого. Общие веса остаются неизменными.
Пока оценок нет, персональной обученной модели также нет.

### Диагностика и адресное расширение покрытия

Пункт **8** в CLI сохраняет `data/personal/coverage.json`. Отдельная команда:

```bash
python -m python_mvp.coverage ~/Downloads/liked.json --run python_mvp/data/expanded-v1/model
```

Отчёт различает распознанное, неоднозначное, присутствующее в исходном датасете
вне каталога и отсутствующее в источнике. Поддержка считается по реальным
пользователям графа, без DEV/SHADOW/FINAL. Названия и ремастеры не доказывают
идентичность аудиозаписей; неоднозначное не объединяется автоматически.

Адресный сбор дополнительной истории для недостающих направлений:

```bash
python -m python_mvp.targeted_data ~/Downloads/liked.json --collect
```

Это **долгая пользовательская команда**. Она читает локальные исходники,
выбирает до 100 пользователей из представительной TRAIN-группы, связанных
с отсутствующими песнями/исполнителями, и получает до 3 страниц по 100 недавних
прослушиваний на человека, в пределах 30 дней. Источник —
[официальный публичный API ListenBrainz](https://listenbrainz.readthedocs.io/en/latest/users/api/core.html).
Это ограниченная выборка, а не выгрузка полной истории; при одинаковых временных
метках на границе страницы часть записей может не попасть в неё.

Без `--collect` команда только сохраняет план — сетевых запросов нет.
API-ответы кешируются под `data/cache/`, запросы имеют описательный User-Agent,
задержку и ограниченные повторы. При повторе используются готовые ответы.
Имена слушателей восстанавливаются из исходных локальных записей и проверяются
по хешам; выборка не берёт пользователей ранжировщика или отложенных сплитов.

Создаётся новый `data/targeted-v1`; прежние данные и модели не меняются.
Разделение пользователей и отметки использования FINAL из источника и модели
сохраняются. После подготовки печатается команда обучения нового графа/модели.
Покрытие может не вырасти: дополнительные истории не гарантируют поддержку
каждого отсутствующего трека. Соседство песен на случайных веб-страницах не
используется как доказательство похожести. Автоматического транслитерирования
с подменой записей и неподтверждённого слияния MBID нет.
